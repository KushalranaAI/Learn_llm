# Rebuild Learn LLM around retrieval and maps

Learn LLM should become a **guided-but-open skill map in which retrieval practice is the main activity**, not a library of pages people read. Five changes matter most. Show a recommended path with soft prerequisites instead of padlocks. Make every lesson a predict, explain, build and recall loop. Run a local spaced-review queue in which build lessons count as review of the concepts they use. End each module with a scaffolded capstone that has checkpoints. Reorder the curriculum so concepts and code are taught together, and evaluation is threaded through the course rather than left to the end. These recommendations rest on strong evidence. Practice testing and spaced practice are the only two study techniques rated "high utility" in the standard review of the field. Learners who predict a demonstration's outcome understand it better, while those who only watch learn about as much as those who never saw it. Whole-task, simple-to-complex instruction design shows large effects in higher education. The UI side has firm precedents too: Exercism's four-state concept map, Khan Academy's mastery levels that can fall as well as rise, and Duolingo's review steps placed on the path itself. The failures are just as instructive: the backlash when Duolingo forced a single line, unreadable many-node graphs, progress percentages that fall when content is added, and streaks that people chase instead of learning. Learn LLM is free, local-first and has no accounts, so it cannot use social or notification mechanics. That costs little, because the elements with evidence behind them are competence feedback, flexible goals and built-in review, and all of them can live in localStorage. The current order is the biggest structural problem: a theory-only module before any code, then a build module that re-teaches the same concepts, with evaluation last. None of the reference curricula examined (Karpathy, Raschka, CS336, fast.ai, Hugging Face, Labonne) is built this way.

## Leading platforms converge on a guided path with escape hatches

Three ways of laying out a course dominate. The first is a **single linear path**. Duolingo moved to this in 2022: each circle is one level of a skill, finished levels turn gold and can be replayed, and units carry headers that name the new concepts plus a "guidebook" of tips ([Duolingo blog](https://blog.duolingo.com/new-duolingo-home-screen-design)). The second is a **prerequisite graph**. Exercism's concept map is a directed graph drawn from prerequisites declared in each exercise's metadata, and its nodes take one of four states. *Locked* means prerequisites are unmet. *Available* means the learning exercise is not yet done. *Complete* means the learning exercise is done but some practice is left. *Mastered* means the learning exercise and all practice are done ([Exercism docs](https://exercism.org/docs/building/tracks/concept-map)). The third is a **hierarchical syllabus**. Codecademy reorganised its career paths into a syllabus of modules, each opening onto a unit page of lessons and projects ([Codecademy blog](https://www.codecademy.com/resources/blog/career-path-redesign)). Khan Academy adds the most useful model for review. Its five mastery levels are Not started, Attempted, Familiar, Proficient and Mastered, and **they can go down**: a Mastered skill drops two levels to Familiar after a score below 70%. Course mastery counts only skills at Proficient or above ([Khan Help](https://support.khanacademy.org/hc/en-us/articles/115002552631)). Khan's own research favours bringing fewer skills to Proficient over spreading many at Familiar ([Khan blog](https://blog.khanacademy.org/?p=13201)). In other words, depth metrics beat breadth metrics.

The failure cases are as useful as the successes. When Duolingo replaced its free-choice tree with the path, learners complained that "you can't choose to study something specific", and a petition asked for the tree back ([PiunikaWeb](https://piunikaweb.com/2022/10/17/duolingo-app-update-with-path-ui-faces-backlash-from-users/); [Change.org](https://www.change.org/p/reverse-duolingo-s-path-update)). The CEO nonetheless reported equivalent engagement ([NBC News](https://www.nbcnews.com/tech/tech-news/duolingos-update-redesign-luis-von-ahn-interview-rcna44655)). Defenders pointed out that the tree had let people skim level 1 everywhere and forget it ([LanguageCrush](https://languagecrush.com/forum/t/3438)). The lesson is that a recommended order helps, while removing all choice provokes resentment. Exercism's Java concept tree became "very hard to follow" because too many practice exercises sat under each concept and implied prerequisites that did not exist ([exercism/java#2631](https://github.com/exercism/java/issues/2631)). The Exercism fix is to **prune transitive edges** and draw only edges from the level directly before ([Exercism docs](https://exercism.org/docs/building/tracks/concept-map)). Codecademy learners complained that hours of work produced only "marginal increases in progress", and the overall percentage can fall when content is added ([Codecademy Help](https://help.codecademy.com/hc/en-us/articles/12941723129627-Career-Path-Syllabus-Updates)). Learn LLM is adding modules, so it will face the same problem.

For "where am I, what's next", the documented patterns are simple. Duolingo has a floating button that jumps back to the learner's current spot on a long path ([Duolingo blog](https://blog.duolingo.com/new-duolingo-home-screen-design)). LMS guidance calls for an always-visible outline, breadcrumbs and "you are here" markers, and names hidden navigation and unclear course length as the main failures ([Lazarev.agency](https://www.lazarev.agency/articles/lms-ux)). Progress indicators belong in one consistent place and support Nielsen's visibility-of-system-status heuristic, but they cannot make a long journey feel shorter ([Uxcel](https://app.uxcel.com/courses/information-architecture/youre-here-navigation-system-654/utilize-progress-trackers-5134)). Lesson layouts are matched to the material. Khan reportedly puts a progress tree, a central explanation area and a practice panel side by side ([Desirability Lab](https://desirabilitylab.com/backfill/backfill-2025-97-khan-academy-course-design)). Brilliant uses short steps that "start with the simplest useful case and increase in complexity" ([Brilliant](https://brilliant.org/resources/choosing-brilliant/how-brilliant-teaches-math/)). Its agency-designed "game feel" layer adds a level gameboard, tiles with tooltips, quiet celebration and encouragement states, and a path that shows "direction and progression while still letting users choose their own route" ([ustwo](https://ustwo.com/work/brilliant)). Showcase galleries yielded almost nothing usable: no 2024–2025 Awwwards Site of the Day for an education platform was found ([Awwwards](https://www.awwwards.com/websites/%23B60165/)). Treat claims about "Dribbble trends" with suspicion. Two notable gaps: **no researched competitor documents keyboard navigation or a command palette**, so these are a chance to stand out rather than a convention to copy, and no current primary source describes roadmap.sh's, Boot.dev's or DataCamp's map interfaces in detail.

## Retrieval, spacing and prediction matter more than interactivity itself

The best-supported finding in learning science is that **retrieving information beats re-reading it**. Dunlosky et al. (2013) rated only practice testing and distributed practice as "high utility". Highlighting and re-reading, the most common student habits, did not consistently help ([APS](https://www.psychologicalscience.org/news/releases/which-study-strategies-make-the-grade.html)). Rowland's meta-analysis puts the typical testing effect at **g = 0.50, 95% CI [0.42, 0.58]** ([Pan & Sana 2021](https://sc-pan.github.io/pdf/PS_2021.pdf)). Adesope et al. found practice tests beat restudying and every other comparison. Mixed-format tests helped more, and benefits peaked when the final test came **1–6 days** after practice ([WSU PDF](https://education.wsu.edu/documents/2018/01/rethinking-use-tests.pdf/)). Spaced retrieval beats massed retrieval by g = 0.74 ([Springer](https://link.springer.com/10.1007/s10648-020-09572-8)). How big the gap between sessions should be depends on how long the learner needs to remember. In Cepeda et al.'s 26-condition study, the best gap rose with the test delay but shrank as a share of it, to about 20% or less at a one-year delay ([Cepeda et al. 2008](https://www.evullab.org/pdf/CepedaVulRohrerWixtedPashler-PS-2008.pdf)). Expanding schedules showed no reliable advantage over uniform ones (g = 0.034 difference) ([Springer](https://link.springer.com/10.1007/s10648-020-09572-8)). Equal spacing gave better long-term retention in Karpicke and Roediger ([WUSTL](https://profiles.wustl.edu/en/publications/expanding-retrieval-practice-promotes-short-term-retention-but-eq/)). At card level, the open FSRS scheduler is well calibrated on roughly 350 million Anki reviews (FSRS-6 log loss 0.346, AUC 0.703) and lets users set a target retention ([srs-benchmark](https://github.com/open-spaced-repetition/srs-benchmark)). Spacing items across sessions matters a great deal. Recalling each item correctly once in each of three spaced sessions gave **68% retention at one week, against 26%** for three correct recalls in one session ([Rawson & Dunlosky 2022](https://journals.sagepub.com/doi/full/10.1177/09637214221100484)). That evidence comes mainly from definitions and vocabulary, and whether it extends to maths procedures is contested ([Higham et al.](https://eprints.soton.ac.uk/449677/1/Higham_et_al._in_press_JEdPsych.pdf)).

Interleaving is narrower than it is often presented. Brunmair and Richter's meta-analysis of 59 studies found **g = 0.42 overall, 0.34 for maths, and no reliable effect for expository text**. The benefit was largest when categories resembled each other and the material was complex ([PubMed](https://pubmed.ncbi.nlm.nih.gov/31556629/)). Interleaving therefore helps learners tell apart things they confuse, such as RMSNorm vs LayerNorm, MHA vs MQA vs GQA, DPO vs PPO vs GRPO, or top-k vs top-p vs temperature. It adds little when the mixed topics are unrelated. Learners consistently misjudge it: nearly 80% thought blocked practice worked as well or better, and the belief survived testing ([Yan, Bjork & Bjork 2016](https://sites.lifesci.ucla.edu/psych-bjorklab/wp-content/uploads/sites/13/2016/11/YanBjorkBjork2016.pdf)). This is part of a broader problem with **self-assessment**. In Deslauriers et al.'s randomised physics comparison, students in active-learning classes learned more but *felt* they learned less, and a fluent lecturer could make students prefer the weaker method ([PNAS 2019](https://openlab.citytech.cuny.edu/gamelab/files/2023/01/Deslauriersa-et-al-2019.pdf)). The design consequence is direct: never let "I understand this" buttons or page completion stand in for mastery.

The question of explaining first versus making learners try first depends on prior knowledge. Worked examples beat unguided problem solving for novices (**g = 0.48**, with very high heterogeneity) ([Barbieri et al. 2023](https://link.springer.com/content/pdf/10.1007/s10648-023-09745-1.pdf)). The advantage reverses as expertise grows ([Springer 2025](https://link.springer.com/article/10.1007/s10648-025-10071-x)), and minimally guided instruction fails novices ([Kirschner, Sweller & Clark](https://classroom.eumetsat.int/mod/resource/view.php?id=4547)). Yet problem-solving *before* instruction outperforms instruction-first for older learners and conceptual goals when it is carefully designed: g = 0.37–0.58 for high-fidelity designs, with a larger bias-corrected headline of 0.87 that has not been reconciled with those figures in the sources reviewed. It reverses for young learners and domain-general skills ([Sinha & Kapur 2021](https://www.x-mol.com/paper/1406031499744456704)). The two camps still disagree. The practical answer is to treat the order as a design choice. Use short "guess first" openers for conceptual ideas, such as why attention scales by √d_k, and explicit worked examples for procedures. Self-explanation prompts add a medium effect (**g = 0.55**), with question-style prompts (g = 0.56) beating instructions (g = 0.40) ([Bisra et al. 2018](https://www.Gwern.net/doc/psychology/spaced-repetition/2018-bisra.pdf)). Barbieri, however, found prompts *weakened* worked-example effects, so prompts should stay light when they sit on top of worked examples. Mayer's multimedia principles set the page rules for maths, code and simulations. His review table gives coherence (cut extraneous material) d = 0.86, signalling d = 0.69 and segmenting d = 0.67 ([EdTech Books](https://edtechbooks.org/docx/10349)). The figures vary between his publications, so treat them as approximate. Pre-training (key terms first) and avoiding redundant narration-plus-text also hold ([Mayer 2020](https://ugc.futurelearn.com/uploads/files/7d/d6/7dd6188d-c343-4311-b064-ac98d2c95abc/Multimedia_Principles._R._E._Mayer__2020.pdf)). One idea can be ruled out entirely: **learning-styles matching has no adequate evidence base** ([Pashler et al. 2008](https://digitalcommons.usf.edu/psy_facpub/1765/)).

The simulations Learn LLM already has need a frame around them. Evidence that interactivity itself teaches is thin. Explorable explanations are a synthesis of theory, not a format validated by experiment ([Distill](https://distill.pub/2020/communicating-with-interactive-articles/)). Their effectiveness "has not been widely studied with real-world audiences" ([UW IDL](https://idl.uw.edu/papers/idyll-analytics)). A 2025 study with 605 participants found AI-literacy simulations helped, but control groups improved too ([arXiv 2507.21090](https://arxiv.org/pdf/2507.21090)). What does have evidence is the activity wrapped around the demo. In Crouch, Mazur et al.'s physics study, students who only watched demonstrations understood no more at semester's end than students who never saw them. Students who **predicted first** understood significantly more ([CORE](https://core.ac.uk/download/76218714.pdf)). Students also rated demonstrations as among the most interesting parts of the course, a reminder that enjoyment is not the same as learning ([Mazur group](https://mazur.harvard.edu/presentations/classroom-demonstrations-learning-tools-or-entertainment)). For code, Parsons problems (reorder the given lines) produce similar learning to writing code from scratch in less time ([escholarship](https://escholarship.org/content/qt8794g5s0/qt8794g5s0.pdf?t=qbddoc); [NSF PAR](https://par.nsf.gov/servlets/purl/10510497)). Subgoal labels on worked examples help most for students at risk of dropping out ([Margulieux et al. 2020](https://doaj.org/article/9a2c85d66fd54ec9ab019e9a510bbf17)). On feedback, research on timing is mixed ([Leiden](https://scholarlypublications.universiteitleiden.nl/access/item%3A2983255/view)). Hints given on request beat hints offered unprompted ([Razzaq & Heffernan](https://web.cs.wpi.edu/~nth/pubs_and_grants/papers/2010/ITS/Razzaq%20Hints%20Is%20It%20Better%20to%20Give%20or%20Wait.pdf)), but learners "game" hint ladders to reach the final hint that gives away the answer. The usual fix is a delay before that last rung ([LearnLab](https://learnlab.org/research/wiki/index.php/Help_abuse)). **Errors made with high confidence are the most likely to be corrected** after feedback (hypercorrection), though they can come back later ([PMC 3079415](https://pmc.ncbi.nlm.nih.gov/articles/PMC3079415)). That justifies asking "how sure are you?" before revealing an answer and putting confident errors first in the review queue.

## Whole-task spirals beat theory-then-build blocks

Sequencing frameworks agree on following prerequisites and moving from simple to complex. They differ on what gets sequenced. Gagné orders atomic skills along a prerequisite chain. Reigeluth's elaboration theory starts from an "epitome", a simplified version of the whole domain, and each pass adds detail ([IU summary](https://idtheory.sitehost.iu.edu/chapter_18_summary.html)). Van Merriënboer's 4C/ID model sequences authentic whole tasks from simple to complex, gives step-by-step procedural information just in time, and fades support within each class of task ([EdTech Books](https://edtechbooks.org/docx/3258)). A meta-analysis of 4C/ID reports **d = 0.79**, and recommends it especially for higher education; that figure comes from the abstract only ([ISCTE](https://repositorio.iscte-iul.pt/handle/10071/23015)). Mastery learning adds roughly **0.5 SD**, with weaker learners gaining most, although Slavin disputed this and other syntheses range from 0.04 to 0.60 ([Skycak](https://justinmath.com/a-brief-history-of-mastery-learning/)). Two adaptive systems turn these ideas into software. In knowledge space theory, the "outer fringe" is the set of items a learner is ready to learn next, and ALEKS teaches from it ([Wikipedia](https://en.wikipedia.org/wiki/Knowledge_space)). Math Academy keeps a second "encompassing" graph alongside its prerequisite graph. Passing an advanced topic gives discounted implicit review credit to the simpler topics it exercises, and slower learners are made to do explicit review instead ([Skycak](https://www.justinmath.com/individualized-spaced-repetition-in-hierarchical-knowledge-structures/)). That last source is the vendor's own design write-up, not an evaluation. Ausubel's advance organizers add a modest, well-replicated benefit across 135 studies ([ITDL review](https://itdl.org/Journal/Jun_09/article01.htm)).

Real LLM curricula follow these principles more closely than Learn LLM's current order does. Karpathy's Zero to Hero is a build in every lecture, introducing each concept exactly when the code needs it ([karpathy.ai](https://karpathy.ai/zero-to-hero.html)). Raschka gives one short conceptual chapter and then interleaves concept and code for tokenization, attention, the GPT model, pretraining and fine-tuning ([rasbt/LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch)). CS336 runs on five whole-task build assignments, and its lectures place **inference (10) and evaluation (12)** among the core systems and scaling material, before post-training ([CS336](http://cs336.stanford.edu/spring2025/)). Labonne's roadmap puts evaluation directly after preference alignment on its Scientist track, and opens its Engineer track with running LLMs and prompting ([mlabonne/llm-course](https://github.com/mlabonne/llm-course)). fast.ai has learners deploy a model in lesson 2, before the foundations ([course.fast.ai](https://course.fast.ai/)). Hugging Face uses Hub models from chapter 1 ([HF course](https://huggingface.co/learn/llm-course/chapter1/1)). Against this background, **Learn LLM's structure is unusual twice over**. Module 01 is eight lessons of theory with no building, and Module 02 then re-teaches the same concepts in PyTorch. Modules 03 (training concepts) and 04 (fine-tuning in code) repeat the same split. The planned post-training-from-scratch module would add a third pass over SFT, preference tuning and GRPO. Evaluation sits last, after prompting, a position none of the references use. No controlled study compares "theory module then build module" with interleaved concept-and-code teaching in ML. The case for restructuring is an extrapolation from 4C/ID, spacing and retrieval research and from expert practice, not a direct test.

## Motivation comes from visible competence, not nudges or streak pressure

Gamification works on average but unevenly. Sailer and Homner's meta-analysis found small positive effects: cognitive g = 0.49, motivational g = 0.36, behavioural g = 0.25 ([Uni Augsburg](https://opus.bibliothek.uni-augsburg.de/opus4/files/109056/109056.pdf)). Their earlier randomised trial showed that elements act through different psychological needs. Badges, leaderboards and performance graphs raised feelings of competence and of the task being meaningful. Stories, avatars and teammates raised relatedness. "Gamification is not effective per se" ([Sailer et al. 2017](https://opus.bibliothek.uni-augsburg.de/opus4/files/109059/109059.pdf)). Gamification can also backfire. A 16-week course with leaderboards and badges saw motivation and satisfaction fall and **final exam scores drop**, with the damage running through intrinsic motivation ([Hanus & Fox 2015](https://dblp.org/rec/journals/ce/HanusF15)). Tangible rewards also undermine intrinsic motivation (Deci, Koestner and Ryan's 128-experiment meta-analysis), though this finding is still contested ([Deci et al. 1999](https://depts.washington.edu/techdocs/papers/deciExtrinsicRewardsAndIntrinsicMotivation99.pdf)). Duolingo's streak numbers need careful reading. "3.6× more likely to complete" for 7-day streakers is a correlation, and committed learners pick themselves into long streaks. The causal A/B gains are small: **+1.7%** seven-day retention from a milestone animation and **+0.38%** daily actives from allowing two streak freezes ([Duolingo blog](https://blog.duolingo.com/how-duolingo-streak-builds-habit)). The most instructive result is that decoupling the streak from a fixed daily goal led fewer learners to hit their goals but raised total learning time ([Duolingo](https://blog.duolingo.com/improving-the-streak)). Flexibility helped. Commentators describe streaks becoming "the point" while learning fades ([UX Magazine](https://uxmag.com/articles/the-psychology-of-hot-streak-game-design)), and a summary of consumer research reports that a broken streak raises the chance of quitting ([The Decision Lab](https://thedecisionlab.com/insights/consumer-insights/streak-creep-the-perils-of-too-much-gamification)). No peer-reviewed study covers streaks for adults teaching themselves technical subjects.

The self-regulation literature points the same way. Zimmerman's cycle runs from forethought to performance to self-reflection ([Wong et al. 2019](https://informahealthcare.com/doi/abs/10.1080/10447318.2018.1543084)). In a correlational meta-analysis, self-evaluation (d = 0.72), self-efficacy (d = 0.70) and task strategies (d = 0.60) were the strategies most strongly associated with achievement, while goal orientation barely registered (d = 0.09) ([Frontiers 2018](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2018.02434/full)). The data are offline and K-12, so the evidence is weak for this context. The sobering result comes from Kizilcec et al.'s study of about 250,000 learners across about 250 MOOCs. Plan-making prompts had **no significant effect on completion**: activity rose for one to two weeks and then faded. An algorithm for targeting interventions did no better than giving everyone the same one ([Cornell Chronicle](https://news.cornell.edu/node/319503)). Four replication RCTs ruled out effects outside −7% to +3% ([Andor et al.](https://rem.rc.iseg.ulisboa.pt/lese/5e3/files/Papers/planning-prompts_Rzepka.pdf)). One detail survives. Plans that named a **specific time of day** predicted completion, but only a quarter of learners wrote one ([Cho et al. 2024](https://spiral.imperial.ac.uk/entities/publication/9ab8818b-ce2d-4b26-8ca4-d7cff15ef324)). Support for self-regulation therefore has to be built into the interface the learner sees every day, not delivered as a one-off onboarding prompt.

## A prioritised blueprint for the redesign

### Restructure the curriculum into an epitome, a build spine and branches

The highest-leverage change is to stop teaching each idea twice with a long gap in between. First, **shrink Module 01 into an epitome of one to three lessons**: tokens, embeddings, attention, next-token sampling and limits, at an intuitive level, with a "use a real model now" moment (move the temperature slider, watch the tokens change). This serves as Ausubel's organizer, as Reigeluth's epitome, and as fast.ai-style early payoff. Second, **merge 01 and 02 into one build spine** in which every topic runs intuition → simulation → code → check. The order would be tokenization (BPE in code), embeddings, attention, the transformer block, training a tiny GPT, sampling, KV cache, then modern architecture (RMSNorm, RoPE, SwiGLU) and MoE. Add a **no-code flag** so learners who only want concepts can skip the code checkpoints without needing a separate module. Third, **organise training, fine-tuning and the planned post-training module by stage** (pretraining data and scaling, SFT, preference/RL, PEFT, distillation), with three depth tiers inside each stage: concept, library practice (TRL/PEFT), and from scratch. Each name then appears once, at three deliberate depths, instead of in three modules. If the modules stay separate, each needs explicit bridges, for example "you met DPO in 03.5; here you run it; next you implement the loss". Fourth, **thread evaluation through the course**: held-out loss and sample inspection in the tiny-GPT build, task evals and LLM-as-judge directly after SFT and preference tuning, and a later advanced module for benchmarks, contamination and agent evals. Fifth, make **Prompt and context a branch unlocked after the epitome**, because it needs only tokens, context windows and sampling, and make **Inference and serving a branch after KV cache and modern architecture**. A team that wants a smaller first step can keep the seven modules but reorder them to 01, 02, 03, 04, Evaluation, Inference, with Prompt offered as an early side branch. Bridging summaries and cross-module review items then give the existing splits a spiral structure.

| Current | Proposed (full) | Rationale |
|---|---|---|
| 01 How LLMs work (8 theory lessons) | 0. Epitome (1–3 lessons, live demo) | Advance organizer, early payoff |
| 02 Build from scratch | 1. Build spine: concept + code per topic, no-code flag | 4C/ID, Raschka/Karpathy interleaving |
| 03 Training + 04 Fine-tuning + planned post-training | 2. Training and post-training by stage, three depth tiers | One spiral instead of three overlapping modules |
| 07 Evaluation (last) | Threaded basics + 3. Advanced evaluation | Placement used by Labonne and CS336 |
| 06 Prompt and context | Branch A after the epitome | Labonne Engineer track, use-first on-ramp |
| 05 Inference and serving | Branch B after KV cache / architecture | Depends on attention cost and KV cache |

### Draw the map at module and lesson level, with five states and a review flag

Store the curriculum as a **static prerequisite DAG in content JSON** with an `encompasses` field, and show it as a recommended path that learners can leave freely. Prerequisites become soft warnings such as "this uses KV cache, which you haven't done: 2-minute check?", not padlocks. Keep each screen to about **7–12 nodes**: modules on the overview, lessons inside a module. Show the ~250 topics only in the lesson outline. Prune transitive edges the way Exercism does. Use node states **Locked/Suggested-later, Available, In progress, Complete and Mastered**, plus an orthogonal **Needs review** flag that clears after a successful recall. Mastered is earned only by **correct delayed recall in three separate sessions**, so it can decay as Khan's levels do. Add a "Skip, I know this" state that a short diagnostic quiz can confirm, which handles expertise reversal for learners who arrive knowing ML. Under the dark theme, reserve emerald for the "current" and "done" states only, and use muted outlines for everything else. Each tile shows an icon for its type (reading, simulation, quiz, lab, code) and an estimated time. On phones the map collapses to a vertical list. Offer goal-based paths (Understand, Build, Fine-tune, Apply) as filters over the same DAG, and compute the knowledge-space "ready to learn" fringe to choose the next step.

### Answer "where am I" everywhere, and make the home screen a review-first launcher

The home screen leads with one **Continue: Module › Lesson › Topic** card, then a **"Review due" count**, then module progress bars with fixed denominators shown at module level, so adding a module never shrinks someone's progress. Course-wide "mastery %" counts only Complete and Mastered lessons. An optional quiet activity heatmap is the most game-like element on the page. The map gets a "jump to current" button. Lessons get a thin sticky progress bar, a collapsible topic outline with per-topic state, and a time-remaining estimate, which answers the "unclear length" complaint. Add **j/k (or arrow) stepping and a ⌘K palette** over modules, lessons, topics and glossary terms. No competitor documents these, so they are a chance to stand out rather than a copied convention. Because progress lives in localStorage, **export and import of progress JSON is a P0 feature**. Losing a browser profile should never wipe someone's record.

### Make every lesson a predict, explain, build and recall loop

Use one lesson template, adjusted for the material. Open with a **pretest or prediction** that is recorded in one tap and shown back after the reveal. Follow with a short explicit segment, where derivations are worked examples annotated next to each step and later steps fade across examples. Next comes the simulation, framed as an experiment: introduce its terms first, start with one control and add more, let the learner step through it rather than autoplay it, and pose "predict the curve, then sweep". Then a code segment: subgoal-labelled PyTorch (`# 1 scores # 2 scale # 3 mask # 4 softmax`) that fades from a full solution to labels only, with Parsons ordering and "find the bug" items (missing `zero_grad()`, wrong softmax axis, a leaking causal mask). Then a one-line **self-explanation prompt** phrased as a question. Close with a mixed-format quiz that includes **one or two items from earlier prerequisite lessons**. Every quiz asks "sure / think so / guessing" before revealing the answer, explains every wrong option, and sends confident errors to the front of the review queue. Hints come as a ladder (nudge, pointer, partial step, full solution) with light friction before the last rung, and hint use is logged for the learner's own information, never penalised. Layout depends on the material. Conceptual and maths topics use a single reading column with inline checkpoints. Simulation topics use a split view on desktop (text left, simulation right) that stacks on mobile with the simulation pinned. Labs get a full-width workbench. Cut decorative asides from the core flow (coherence principle). Keep celebrations to brief micro-feedback and save the bigger moment for finishing a module.

### Run review locally, with build work counting as review

Build a **two-layer review system** in localStorage. Concept, formula and glossary cards (the existing glossary and interview JSON are ready-made sources) are scheduled with **FSRS via `ts-fsrs`** at a desired retention of about 0.85–0.90. That target is a design judgement, not a research finding. Lesson-level revisits come at roughly **1 day, 1 week and 1 month**, as short quizzes rather than "re-read this lesson". Review sets interleave **confusable pairs** (LoRA/QLoRA/full fine-tuning, DPO/PPO/GRPO, KV cache/prompt caching, RMSNorm/LayerNorm) and avoid mixing unrelated topics. Math and code items use fresh variants on each pass. Apply Math Academy's encompassing idea: finishing "write causal self-attention" pushes back the review clocks for softmax, dot products, masking and shapes, which keeps the daily review load manageable. Because self-paced learners skip days, the queue has to handle overdue items gracefully and cap its daily size. Tell learners briefly why review feels harder than re-reading, though the Bjork findings suggest the explanation will not fully change their beliefs.

### Turn labs into scaffolded capstones with checkpoints that can be verified offline

Each module ends with one **integrative capstone that is also cumulative review**. Examples: train a tiny GPT for the build spine, and for fine-tuning, apply LoRA then DPO and evaluate against the base model. Each capstone fades its support in the 4C/ID pattern: a fully worked notebook, then a completion version with blanks for attention and the training loop, then a spec-plus-tests version. Run it on a three-tier ladder: a simulation in the page, a NumPy cell in the page via Pyodide/JupyterLite, which can now run NumPy and Matplotlib teaching with no server ([Zonca 2026](https://www.zonca.dev/posts/2026-05-18-jupyterlite-no-server-needed)), and then Colab or local PyTorch. Whether PyTorch runs under Pyodide was not verified, so plan on full PyTorch staying in Colab or local runs. For the Colab and local tier, verify progress through **deterministic checkpoint values**: the notebook prints the loss at step 100 under a fixed seed, or a tensor hash, and the learner pastes it back for comparison in the browser. This design idea is not established practice, but it gives local-first verification with no server. It also extends the existing predict, then compute by hand, then meet goals lab pattern, which already matches the evidence.

### Motivate through competence and autonomy, and leave out the rest

Use the Sailer competence elements: mastery maps, progress graphs, "you predicted X of Y correctly", a personal **calibration chart** of confidence against accuracy, and visible skill unlocks. Support autonomy with goal-based paths, optional challenge modes and **learner-set weekly goals with a chosen day and time**, exportable as an .ics file in place of the push notifications a no-account web app cannot send reliably. The "you are building a GPT" storyline is a weak but free substitute for relatedness, alongside links to outside communities. If a streak exists at all, make it **weekly, forgiving, with built-in freezes, and separate from any quota**. Leave out leaderboards, XP as the main currency, loss-framed messages, guilt copy, generic motivational value prompts (which backfired for some groups in Kizilcec et al.), "mark as read" as a mastery signal, highlighter-centred study modes, and any learning-style quiz.

## Conclusion

Most "learning platform redesigns" concentrate on the map, but the research suggests the map is the least important part. A map only tells learners what exists. What decides whether Learn LLM actually teaches is whether learners **retrieve, predict and build again and again**, spread across days. Its simulations, quizzes and labs already put it ahead of most competitors on raw ingredients. The weaknesses are in how those pieces connect: review is not scheduled, a lesson finished once counts the same as something mastered, and the curriculum delays building and then teaches every concept twice. Fixing those connections costs less than a visual overhaul and does more.

The local-first constraint turns out to be an advantage. The motivation mechanics Learn LLM cannot build (leaderboards, push nudges, streak anxiety) are the ones with weak, contested or negative evidence. The ones it can build entirely in the browser have the best support: a prerequisite DAG, a review queue, confidence calibration, encompassing review credit and checkpoint-verified capstones. The open questions are ones the platform could answer itself. Nobody has tested theory-then-build against interleaved teaching for ML, checkpoint verification, or how long an epitome should be. An opt-in, exportable local analytics log would let Learn LLM generate the evidence these reports could not find.
